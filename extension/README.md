# 방문기록 트래커

Chrome 확장 프로그램. 방문한 페이지의 URL, 제목, 본문 텍스트 전체를 **본문 추출이 끝나는 즉시** `{API 서버 주소}/collect`로 전송합니다.

## 설치 (개발자 모드)

1. `chrome://extensions` 접속
2. 우측 상단 "개발자 모드" 켜기
3. "압축해제된 확장 프로그램을 로드합니다" 클릭 → 이 폴더(`extension`) 선택
4. 확장 아이콘 → "설정 열기" → API 서버 주소(예: `http://127.0.0.1:8000`) 입력 후 저장
5. 확장 아이콘 팝업의 "수집 상태" 토글로 언제든 수집 켜기/끄기 가능. 끄면 새로운 페이지를 수집하지 않습니다.

## 전송 데이터 형식 및 전송 시점

페이지 로드가 끝나 본문을 추출한 시점에 **바로** POST합니다. 방문이 끝날 때까지 기다리지 않으므로 탭을 옮기거나 브라우저를 그냥 종료해도 이미 추출된 본문은 유실되지 않습니다.

```json
POST {API 서버 주소}/collect
{
  "url": "https://...",
  "title": "페이지 제목",
  "startTime": "2026-08-24T12:00:00.000Z",
  "content": "본문 텍스트 일부..."
}
```

`startTime`은 본문을 추출해 전송한 시각입니다. 체류시간은 수집하지 않습니다 — 로컬 검색용이라 "얼마나 오래 봤는지"보다 "무엇을 봤는지"만 남기면 충분하고, 체류시간을 재려면 방문이 끝날 때까지 본문을 들고 있어야 해서 그 구간에서 본문이 유실되곤 했습니다.

전송이 실패하면(오프라인, 서버 다운 등) 해당 건만 로컬 재시도 큐에 남아 30초마다 재시도합니다. 성공한 건은 큐에 들어가지 않습니다. 큐는 최대 300건까지만 보관하며, 넘치면 오래된 건부터 버립니다 — 항목마다 본문 전체가 들어가서 서버를 꺼둔 채로 오래 브라우징하면 브라우저가 확장에 주는 저장 공간을 넘기게 됩니다.

## 수집 범위

**열린 페이지는 전부 수집합니다.** 배경 탭에서 로드된 페이지, 포커스가 없는 창의 페이지도 포함됩니다. 뒤집어 말하면 링크를 새 탭으로 열어두기만 하고 실제로 보지 않은 페이지도 기록에 남습니다.

## 알려진 제약

- **시크릿 모드**: 사용자가 `chrome://extensions`에서 "시크릿 모드에서 허용"을 직접 켜야만 수집됩니다 (확장 프로그램 코드로 강제 불가).
- **SPA 본문 재추출**: `history.pushState` 기반 라우팅 시 본문을 다시 추출하도록 콘텐츠 스크립트에 요청하지만, 렌더링이 800ms보다 늦게 끝나는 페이지는 이전 본문이 잡힐 수 있습니다.
- **로드가 끝나야 수집**: 본문 추출은 `window.load` 이후에 일어납니다. 로드가 끝나지 않는 페이지(무한 스트리밍 등)는 수집되지 않습니다.
- **메인 프레임만**: 콘텐츠 스크립트가 최상위 프레임에만 주입되므로, 본문이 iframe 안에 있는 사이트는 본문이 비어 있게 됩니다.
- **본문은 텍스트만**: 원본 HTML이 아니라 [Mozilla Readability](https://github.com/mozilla/readability)(`Readability.js`)로 파싱한 본문 텍스트(광고/네비게이션/사이드바 등 제거된 기사 본문)입니다. 기사형 콘텐츠가 아닌 페이지(예: 검색결과, 대시보드)는 Readability가 파싱에 실패하거나 빈약한 결과를 줄 수 있는데, 이 경우 `document.body.innerText`로 자동 폴백합니다.
